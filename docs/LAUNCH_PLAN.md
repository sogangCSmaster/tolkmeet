# 출시 계획 (도메인 구입 이후)

도메인(`tolkmeet.com`)을 사면 진행할 일의 설계와 순서. 아직 구현하지 않았다. 결정이 바뀌면 이 문서를 고친다.

## 1. 도메인 구조

| 주소 | 내용 | 호스팅 | 색인 |
|---|---|---|---|
| `tolkmeet.com` | 소개 페이지(SEO), 요금, 약관, FAQ. 정적 HTML | **GitHub Pages**(무료, HTTPS 자동) | 색인함 |
| `www.tolkmeet.com` | `tolkmeet.com`으로 이동(Pages가 자동 처리) | GitHub Pages | — |
| `meet.tolkmeet.com` | 지금 앱 그대로(로그인·회의·대면·자막 화면). 회의 링크는 `meet.tolkmeet.com/abcd-efgh-ijkm` | **AWS Lightsail**(Caddy + Rust 서버 + coturn) | `noindex` + `robots.txt` 전부 막음 |

**나누는 이유**
- 소개 페이지는 검색 엔진이 읽을 수 있는 정적 HTML이어야 한다. 지금 앱은 React SPA라 첫 응답이 빈 `<div id="root">`다. 소개 페이지를 앱 안에 두면 SSR·프리렌더를 앱에 붙여야 하고, 그만큼 앱이 무거워진다.
- 앱은 카메라·마이크·WebRTC 때문에 바뀌는 일이 잦다. 소개 페이지와 배포를 따로 하면 서로 깨뜨리지 않는다.
- 회의 링크가 `meet.`로 시작하면 받는 사람이 "화상회의 링크"라고 바로 안다(Google Meet와 같은 감각).
- 세션 쿠키는 `meet.`에만 걸린다(Domain 속성 없이). 소개 페이지는 쿠키를 읽지도, 받지도 않는다.

**apex(`tolkmeet.com`)와 `www` 중 하나**는 정해서 다른 쪽을 301로 보내면 둘 다 SEO에 문제없다. 짧은 apex를 권장한다. `www`를 대표로 해도 된다.

**속도**: 소개 페이지는 JS 없는 정적 HTML이라 첫 화면이 가장 빠르다(Pages는 Fastly CDN). 앱에는 영향이 없다.

**GitHub Pages로 두는 것**(결정, 2026-10-17)
- 서버비 0, 소개 페이지 트래픽이 몰려도 앱 서버에 부담이 없다. 레포가 공개(AGPL)라 무료로 쓸 수 있다.
- 배포: `site/`가 바뀌면 GitHub Actions가 빌드해 Pages에 올린다. 사용자 지정 도메인은 DNS에 GitHub Pages IP(A·AAAA)와 `www` CNAME, 레포 설정에서 HTTPS 강제.
- 한계: 응답 헤더(CSP·캐시 기간)를 직접 정할 수 없다. 정적 소개 페이지라 큰 문제는 아니다(CSP는 `<meta>`로). 월 대역폭 약 100GB(권장치)라 이미지는 가볍게.
- 앱(`meet.`)과 주소가 달라 쿠키·로그인이 섞이지 않는다. "로그인"·"시작하기" 버튼은 `meet.tolkmeet.com/login`, `/signup`으로 보낸다.

## 1-1. 레포 구성(모노레포)

한 레포에 세 부분을 둔다. 배포 대상이 다르므로 빌드도 따로 한다.

```
server/   Rust 서버            → AWS (meet.tolkmeet.com)
web/      React 앱             → AWS (Caddy가 정적 파일로 서빙)
site/     Astro 소개 페이지     → GitHub Pages (tolkmeet.com)
design/   토큰·워드마크(공용)   → web·site가 함께 가져다 씀
docs/
```

- `web/`과 `site/`는 각자 `package.json`·잠금 파일을 가진 독립 프로젝트로 둔다(작업 공간으로 묶으면 지금의 `pnpm --dir web` 명령·스크립트가 바뀌는데 얻는 것이 적다). 공용 디자인은 `design/tokens.css`를 두 곳이 가져다 쓴다(`site/`는 CSS `@import`로). 브랜드 마크와 데모 얼굴은 작은 SVG라 각 프로젝트에 같은 그림을 두고, 바꿀 때 둘 다 고친다.
- **GitHub Actions로 배포하는 것은 랜딩페이지(`site/**` → GitHub Pages)뿐이다.** 공개 저장소이므로 앱(`server/**`·`web/**`)의 배포 비밀정보(SSH 키·API 키)를 CI에 두지 않는다. 앱은 운영자가 자기 컴퓨터에서 배포 스크립트(`deploy/deploy.sh`)로 Lightsail 서버에 올린다.

## 2. 회원가입·로그인

지금은 운영자가 `HOST_ACCOUNTS` 환경 변수에 해시를 넣는 방식이고, 세션은 서버 메모리에 있다. 바꿀 점:

- **저장소: SQLite, 서버 프로세스 안에** (`rusqlite`, WAL 모드, 같은 서버의 로컬 디스크 파일). 네트워크 왕복이 없어 조회가 마이크로초 단위이고, 따로 운영할 DB 서버도 없다. 표: `users`, `sessions`, `email_tokens`, `subscriptions`, `usage`. 서버 재시작에도 로그인이 유지된다.
  - 쓰기는 한 번에 하나라 연결 하나를 전용 스레드(또는 `spawn_blocking`)에 두고, 비동기 작업이 DB를 기다리며 잠금을 쥐지 않게 한다(서버는 잠금을 쥔 채 await하지 않는다는 규칙 그대로).
  - Paddle 동의 철회: privacy@로 요청을 받으면 `UPDATE users SET paddle_consent_withdrawn_at = unixepoch() WHERE email = '…'`로 기록한다(초 단위). 그 뒤 요금제를 바꾸려면 결제 화면에서 두 동의를 다시 체크해야 하고, 새 결제도 매번 동의를 받으므로 그때 철회 기록이 지워진다.
  - 백업: 한 대에 모든 데이터가 있으므로 **Litestream으로 S3에 연속 복제**한다(초 단위 지연, 인스턴스가 사라져도 복구). 앱 성능에는 영향이 없다.
    보관은 `retention: 23h`, `retention-check-interval: 1h`(기본값)로 둔다. 가장 오래 남는 시간은 retention + check interval이므로 합이 24시간을 넘지 않게 한다.
    S3 버킷 버전 관리는 끈다(켜면 지운 파일이 옛 버전으로 남는다). DB는 `secure_delete = ON`으로 지운 행(한 페이지를 넘는 큰 값 포함)을 0으로 덮어 파일·스냅숏에 남기지 않는다.
    개인정보 처리방침이 "계정을 지우면 백업 사본도 하루쯤 안에 지운다"고 약속하므로 늘리면 처리방침도 함께 고친다.
- **로그인 방식**
  1. **Google 로그인(OIDC)**: B2B 사용자에게 가장 마찰이 적다. 처음 받는 정보는 이메일·이름뿐.
  2. **이메일 + 비밀번호**: argon2id(지금 쓰는 것), 이메일 인증 필수, 비밀번호 재설정 링크(1회용, 30분). 메일 발송은 **Cloudflare Email Sending**(아래).
  - 잠금·지연 비교 같은 지금의 로그인 보호는 그대로 둔다.
- **게스트는 계속 가입 없이** 링크로 들어온다(가장 큰 장점). 계정은 회의를 만드는 사람만 필요하다.
- `HOST_ACCOUNTS`는 운영자 계정용으로 남긴다(관리 화면, 사용량 확인).
- **메일 발송: Cloudflare Email Sending** (결정 2026-10-18. REST API 하나, Rust에서 `reqwest`로 호출, SDK 불필요)
  - 도메인과 DNS가 이미 Cloudflare에 있어 업체가 하나 줄고, 도메인 등록(Onboard Domain) 때 SPF·DKIM(`cf-bounce` 하위 도메인)·DMARC 레코드를 Cloudflare가 넣어 준다.
  - 2026-04-16부터 공개 베타. 임의의 받는 사람에게 보내려면 Workers 유료 플랜(월 $5)이 필요하다. 가격은 월 3,000통 포함, 그 뒤 1,000통당 약 $0.35(제3자 비교 자료 기준, 공식 가격표로 다시 확인).
  - 토큰은 `Email Sending: Edit` 권한만 준 API 토큰. 보내는 주소는 등록한 도메인의 `no-reply@tolkmeet.com`(하위 도메인 등록 방법은 문서에 없어 본 도메인으로 보낸다).
  - 베타라 막히면 Resend나 AWS SES로 옮긴다(발송 코드는 `mail.rs`의 함수 하나로 감싸 두었다). 받는 메일(support@·privacy@·billing@)은 Cloudflare Email Routing으로 운영자 메일함에 전달한다.
  - **메일 언어**: 받는 사람이 가입할 때 보던 화면 언어(en·ko·ja)로 보낸다. 가입 시 `locale`을 계정에 저장하고, 화면 언어를 바꾸면 함께 갱신한다. 회의 초대 메일은 보내는 사람이 고른 언어(기본은 보내는 사람의 언어).
  - 메일 속 링크는 1회용 토큰(32바이트 랜덤, DB에는 해시만), 30분 만료. 같은 주소로 1분에 1통, 하루 5통으로 제한해 메일 폭탄·비용 남용을 막는다.
- 계정 삭제(셀프)와 데이터 내보내기: 개인정보 처리방침에 넣어야 하므로 처음부터 만든다.

**속도**: 로그인 화면만 바뀐다. 회의 입장·자막 경로에는 DB 조회가 들어가지 않는다(세션 확인은 메모리 캐시).

## 3. 결제 (Paddle)

Paddle은 **판매 대행자(Merchant of Record)**다. 나라별 부가세·영수증·환불·카드사 분쟁을 Paddle이 맡는다. 1인 사업자가 해외에 팔기에 가장 부담이 적다.

- **흐름**: 요금 페이지 → `meet.`에서 로그인 → Paddle.js 오버레이 결제(카드 정보는 Paddle만 본다) → Paddle **웹훅**(`/api/paddle/webhook`) → 서버가 서명(`Paddle-Signature`, HMAC-SHA256)을 검증하고 `subscriptions` 표를 갱신 → 사용 권한 반영.
- **권한 판단은 서버에서만**: 결제 상태는 웹훅으로만 바뀐다. 브라우저가 보낸 "결제 완료"는 믿지 않는다.
- **사용량 한도를 거는 곳**: 지금 서버가 음성 인식 토큰을 내주는 지점(`stt_token`)이 이미 유일한 관문이다. 여기서 "이번 달 남은 번역 시간"을 확인하면 된다. 번역 시간은 서버가 받은 `stt` 확정 구간 길이로 센다(브라우저가 보내는 값만 믿지 않도록 토큰 발급 수·세션 시간과 함께 본다).
- **고객 포털**: 구독 변경·취소·영수증은 Paddle 고객 포털 링크로(직접 만들지 않는다).
- **순서**: Sandbox 계정으로 개발 → 실제 계정 심사(도메인 검증, 아래 페이지들이 공개돼 있어야 함) → 전환.
- **Paddle 심사 전에 필요한 것**: 공개된 소개 페이지, 요금 페이지(가격이 보여야 함), 이용약관, 개인정보 처리방침, **환불 정책**, 연락처. 제품이 실제로 동작해야 한다.

**속도**: Paddle.js는 결제 버튼을 누를 때만 불러온다(소개 페이지·회의 화면에는 없음).

## 4. 요금제 (초안)

경쟁 서비스 조사와 원가를 바탕으로 정한다. 조사 결과는 아래 "경쟁 서비스 요금"에 있다.

원가(추정, 2026-10 공식 단가 기준): 1:1 화상회의 1시간에 약 $1~1.5(음성 인식 약 $0.45 + 번역 약 $0.6~1.0). 3개 언어 4인 회의는 약 $2~3. 실제 원가는 서버에 Gemini 토큰 사용량 합계를 남겨 측정한다(출시 전 할 일).

원칙:
- 원가가 사용 시간에 비례하므로 **무제한 정액은 하지 않는다**. "월 N시간 포함 + 초과 시 업그레이드".

- 게스트는 무료(회의를 만든 사람의 시간에서 차감).
- Paddle 수수료(거래당 5% + $0.50)를 원가에 넣는다.
- **비용 안전장치**(요금제와 별개로 꼭 둔다):
  - 계정마다 월 한도를 넘으면 음성 인식 토큰을 내주지 않는다(서버에서 강제).
  - **전체 하루 지출 상한**: 서버가 오늘 쓴 Gemini 토큰을 합산해 운영자가 정한 금액을 넘으면 새 토큰 발급을 멈추고 운영자에게 알린다(차단기). 버그나 남용이 있어도 손실이 하루 상한을 넘지 않는다.
  - Google Cloud 결제 예산 알림(50·90·100%).
- 고정비: Lightsail micro 한 대(월 $7, 공인 IPv4·전송량 2TB 포함) + Cloudflare Workers 유료($5, 메일 발송) + 도메인.
  - **서버 결정(2026-10-18)**: EC2 t4g.small(디스크·IPv4 포함 월 약 $19.7) 대신 Lightsail micro(1GB, 월 $7). 실행 파일 하나 + SQLite라 1GB로 넉넉하고(운영 중 약 330MB), 전송량이 묶여 있어 TURN 중계에 유리하다. Lightsail에는 인스턴스 역할이 없어 S3 백업은 버킷 하나에만 쓸 수 있는 키를 서버에 둔다. 하드웨어 장애 자동 이전(EC2 auto recovery)은 없으므로 상태 점검 알림 + 매일 자동 스냅샷 + `deploy/restore-from-snapshot.sh`로 대비한다.
  - 트래픽: TURN 중계로 영상이 서버를 지나가는 회의는 시간당 약 1GB 남짓을 쓴다(P2P가 되는 회의는 0). Lightsail 포함 전송량 2TB 안에서는 추가 비용이 없다.

## 5. 소개 페이지(SEO)

**기술**: `site/` 폴더에 Astro로 만든다. 결과물은 JS 없는 정적 HTML이고, 언어별 경로·사이트맵을 기본 기능으로 지원한다. 디자인 토큰(`design/tokens.css`)과 워드마크·로고를 앱과 같이 쓴다. 홈 데모(움직이는 자막 예시)는 작은 스크립트 하나로 그대로 옮긴다.

**언어**: `/`(영어), `/ko/`, `/ja/`. `hreflang`과 `canonical`을 넣는다. 브라우저 언어로 자동 이동하지 않는다(검색 로봇이 한 언어만 보게 됨). 대신 언어 선택을 눈에 띄게 둔다.

**페이지**
| 경로 | 목적 |
|---|---|
| `/` | 첫 화면: 한 문장 가치 제안 + 움직이는 데모 + "시작하기" |
| `/pricing` | 요금(Paddle 심사 필수) |
| `/use-cases/…` | 상황별: 한·일 비즈니스 미팅, 투자·IR, 무역·바이어 상담, 병원·관광 안내(대면 모드), 세미나 자막 화면 |
| `/compare/…` | "Google Meet 번역 대안", "Zoom 번역 자막 대안" 같은 비교(검색 수요가 있는 말) |
| `/faq` | 질문 모음(FAQ 구조화 데이터) |
| `/terms`, `/privacy`, `/refund` (+ `/ko/…`) | 약관(영문·한국어) |

**첫 화면 구성(제대로 만들 때)**
1. 히어로: 제목·설명·버튼 2개(시작하기 / 회의 화면 보기) + 지금 홈의 움직이는 회의 예시.
2. 세 가지 모드: 화상회의 · 대면 대화 · 자막 화면(탁자 위 태블릿). 각각 실제 화면 캡처.
3. 어떻게 쓰나(3단계): 링크 보내기 → 각자 자기 언어 고르기 → 말하면 자막.
4. 왜 다른가: 앞뒤 대화를 보고 번역(LLM 문맥 번역), 말이 끝나고 1.5초 안에 번역, 한국식 발음 일본어도 알아듣기, 설치·가입 없이 게스트 입장.
5. 개인정보: 영상은 P2P, 자막은 서버에 저장하지 않음, 오픈 소스.
6. 요금 요약 → `/pricing`.
7. FAQ 5~6개.
8. 꼬리말: 약관 링크, 언어 선택, 연락처, "오픈 소스(AGPL-3.0) · GitHub" 링크(GitHub 아이콘). 앱(`meet.`) 홈에 있던 소스 안내는 2026-10-17에 빼고 여기로 옮긴다.

**기술적인 SEO**
- 페이지마다 `title`·`description`·OG 이미지(1200×630, 언어별)·`canonical`·`hreflang`.
- `sitemap.xml`, `robots.txt`(앱 하위 도메인은 전부 막음).
- 구조화 데이터: `SoftwareApplication`(가격 포함), `FAQPage`, `Organization`.
- Core Web Vitals: 이미지 AVIF/WebP + 크기 지정, 폰트는 지금처럼 Pretendard dynamic subset 하나. 목표 LCP 1초대.
- Google Search Console·네이버 서치어드바이저 등록. 분석은 쿠키 없는 도구(Plausible 또는 Cloudflare Web Analytics)로 하면 쿠키 동의 배너가 필요 없다.

## 6. 약관 (영문)

| 문서 | 꼭 들어갈 것 |
|---|---|
| Terms of Service | 서비스 내용, 계정 책임, 금지 행위, 구독·자동 갱신·해지, 번역 정확도 보증 없음(통역 대체 아님), 책임 제한, 준거법, AGPL 소스 공개와의 관계 |
| Privacy Policy | 수집 항목(이메일·이름·결제는 Paddle), **회의 음성이 Google Gemini로 전송되어 처리됨**(처리 위탁·국외 이전), 자막·음성을 서버에 저장하지 않음, 영상은 P2P(TURN 중계 시 서버 경유하지만 저장 안 함), 보관 기간, 삭제 요청, 쿠키(필수 쿠키만), 연락처 |
| Refund Policy | Paddle 심사 필수(14–90일, 조건 없는 환불). 결정: 모든 결제 30일 안에 이유 없이 전액 환불 |

주의:
- **한국 이용자**: 개인정보 보호법상 처리방침은 이용자가 이해할 수 있게 공개해야 하고, 국외 이전(Google·Paddle)을 알려야 한다. 영문을 기준 문서로 두되 **한국어 번역본도 함께 두는 것을 권장**한다. 일본(개인정보보호법)도 같은 이유로 일본어본이 있으면 좋다.
- Gemini는 **유료 티어만** 쓴다(무료 티어는 입력이 모델 개선에 쓰일 수 있음). 처리방침에 이 점을 적는다.
- 사업자 등록·통신판매업 신고 필요 여부, 약관 최종 문구는 출시 전에 전문가 검토를 받는다.

## 7. 순서

1. 도메인 구입, DNS(Route 53 또는 Cloudflare): apex·`www` → GitHub Pages, `meet.` → Lightsail 고정 IP(DNS only), 메일용 SPF·DKIM·DMARC.
2. SQLite + 회원가입·로그인(Google, 이메일).
3. 사용량 측정(번역 시간·Gemini 토큰)과 요금제 한도.
4. 소개 페이지 + 요금·약관·환불 페이지(영·한·일).
5. Paddle Sandbox 연동 → 심사 신청 → 실제 결제.
6. Search Console 등록, 사이트맵 제출, 비교·사례 페이지 추가.
